# 0.16.0 重启后验收清单

> 用途：0.16.0 已安装到桌面端 profile，但**运行中的 DSH Desktop 仍是旧版**。请先重启 DSH Desktop
> （不是重启当前会话），然后逐条核对下面 8 项。每项都写清「怎么看 / 期望什么 / 不通过时贴哪行日志」。
> 验收不通过时：把对应日志行（或截图里的报错）贴回任务，不要只写「不行」。

## 0. 先确认版本真的加载了

- **怎么看**：打开「设置 → 避峰岗」，看标题下方的版本；或看
  `C:\Users\29805\AppData\Roaming\dsh-desktop\harness\plugins\dsh-peak-valley-router\debug.log` 最后几行。
- **期望**：设置页显示 `版本 v0.16.0`；`debug.log` 出现
  `apply: v0.16.0, enabled=…, …`。
- **不通过时贴**：`debug.log` 里最新那条 `apply:` 行（整行，含时间戳），以及设置页版本截图/文字。
- 备注：若仍是 `apply: v0.12.0`/`v0.15.0`，说明重启没生效或加载了旧 generation——直接回报，不要继续往下验。

## 1. 三档卡片可配

- **怎么看**：设置页中部应有三张档位卡片：低档 / 中档 / 高档。
  中档、高档默认勾选「跟随低档」并只读显示继承来的谷时/峰时配置；取消勾选后变为可编辑。
  低档始终独立可编辑（谷时模型、`costRouting`、峰时开关/星期/窗口/峰时模型）。
- **期望**：三张卡片都在；中/高默认「跟随低档」；取消跟随后能独立改模型与峰谷表；再勾回跟随会恢复继承值。
- **不通过时贴**：设置页截图 + 浏览器/desktop 控制台报错（如有），并说明是哪张卡片哪一步失败。

## 2. 每档峰谷表可配

- **怎么看**：分别在低/中/高三档卡片里：改「谷时模型」下拉、打开「启用峰时」、勾选星期、增删峰时窗口、选峰时模型。
- **期望**：每档都能独立保存；中/高在跟随状态下只读，取消跟随后可独立配置；保存后重新打开设置页值仍在。
- **不通过时贴**：`debug.log` 里保存那次的 `set:` 行；若保存报错，贴设置页错误横幅原文。

## 3. 峰谷窗口与节假日可编辑

- **怎么看**：设置页「节假日」与峰时窗口编辑区。
  节假日：按年分组，可增删日期，可用内置 2025/2026/2027 整年预设一键导入。
  窗口：每档可增删 `start/end`；尝试输入 `start >= end` 或跨午夜（如 23:00–01:00）。
- **期望**：节假日增删/预设导入正常；非法窗口就地报错（不保存脏数据）；合法窗口保存后重新打开仍在。
- **不通过时贴**：出错时的 UI 提示原文 + 当时输入的窗口值；保存失败贴 `debug.log` 的 `set:` 行。

## 4. 智能程度路由默认关

- **怎么看**：设置页「智能程度路由」总开关与两个阈值输入框。
- **期望**：开关**默认关闭**；关闭时两阈值仍可见但灰显/只读（或按当前实现灰显）；打开后可编辑阈值；
  样例试算（probe）能给出分数/档位/目标。关闭时行为与 0.15 一致（恒低档）。
- **不通过时贴**：开关初始状态截图；若 probe 报错，贴 UI 错误原文与 `debug.log` 对应行。

## 5. 目标≠会话模型不报错（新接缝）

- **怎么看**：打开「启用避峰岗」并保持智能程度路由关闭；在**新会话**里发一条普通消息
  （可在设置页把低档谷时模型改成与当前会话不同的模型，制造 `目标 != 会话模型`）。
  然后看 `debug.log`。
- **期望**：回合正常完成（不再出现旧版的
  `agent/request proposed … after step preparation fixed … use agent.model.select()` 报错）；
  日志依次出现 `inbox: decision …` → `inbox: select -> …` → `pre-step: … match=true` → `request: observed …`。
- **不通过时贴**：整个回合的 `debug.log` 片段（至少 decision/select/pre-step/request 四行，各含时间戳），
  以及会话里出现的报错原文。

## 6. 告警可见（不可路由目标）

- **怎么看**：在设置页把低档（或当前档）谷时模型临时改成一个**不存在的模型名**（例如手动改 `policy.json`
  的 `targets.low.valley.model` 为 `no-such-model`，保存/重启插件后生效）；发一条消息，再打开设置页。
  验完务必改回原模型并保存。
- **期望**：设置页顶部出现红/黄告警横幅（可展开多条），`debug.log` 出现 `warning: …`；
  会话仍能继续（保持原模型，不崩）。改回后告警应自动清除（`recentWarnings` 里能看到 cleared 历史）。
- **不通过时贴**：设置页告警横幅截图/文字 + `debug.log` 中对应 `warning:` 行（含 `kind`/`target`）。

## 7. 恢复原模型

- **怎么看**：在设置页点「恢复原模型」（单条或全部），或关闭「启用避峰岗」开关。
- **期望**：当前会话/目标会话的模型恢复为插件接管前的原模型；`get` 的 `applied` 被清除并持久化到
  `state.json`（`applied`/`restore` 字段变化）；重新打开设置页状态仍一致。
- **不通过时贴**：`debug.log` 的 `restore:` 行，以及 `state.json` 中 `applied`/`restore` 的当前值
  （路径 `…\harness\plugins\dsh-peak-valley-router\state.json`）。

## 8. 跨窗口/多进程同步（可选，但建议）

- **怎么看**：打开两个 DSH 窗口，在 A 里切换某会话开关/改策略并保存，等 3 秒看 B 的设置页/开关。
- **期望**：B 在约 3 秒内跟随（页面可见时）；若 B 正在编辑草稿，则出现「重新加载 / 用我的覆盖」冲突条，
  不静默覆盖。
- **不通过时贴**：两边 `debug.log` 对应时间段的行 + 冲突条截图（或说明 B 无变化）。
